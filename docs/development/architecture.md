# 项目架构

本文档详细说明 Note Studio 的架构设计。

## 整体架构

```
┌─────────────────────────────────────────────┐
│          apps/desktop (应用层)               │
│  - Electron 主进程                           │
│  - 窗口管理、系统集成                         │
├─────────────────────────────────────────────┤
│  @note-studio/ui (UI 层)                    │
│  - React 组件库                              │
│  - 主题样式                                  │
├─────────────────────────────────────────────┤
│  @note-studio/editor (编辑器层)             │
│  - Monaco 编辑器                             │
│  - Markdown 编辑器                           │
├─────────────────────────────────────────────┤
│  @note-studio/plugin-system (插件层)        │
│  - 插件 API                                  │
│  - 插件管理                                  │
│  - 命令系统                                  │
├─────────────────────────────────────────────┤
│  @note-studio/knowledge-base (知识库层)     │
│  - 文档索引                                  │
│  - 向量搜索                                  │
│  - RAG 系统                                  │
├─────────────────────────────────────────────┤
│  @note-studio/ai (AI 服务层)                │
│  - AI 提供商                                 │
│  - 模型管理                                  │
├─────────────────────────────────────────────┤
│  @note-studio/core (核心层)                 │
│  - 主题系统                                  │
│  - 工作区管理                                │
│  - 设置管理                                  │
├─────────────────────────────────────────────┤
│  @note-studio/shared (基础层)               │
│  - 类型定义                                  │
│  - 工具函数                                  │
│  - 常量定义                                  │
└─────────────────────────────────────────────┘
```

## 包职责

### 1. `@note-studio/shared` - 共享代码

**职责**：
- 提供所有包共享的类型定义
- 提供通用工具函数
- 定义常量和协议

**依赖**：无

**特点**：
- 基础包，不依赖其他包
- 被所有其他包依赖

### 2. `@note-studio/core` - 核心功能

**职责**：
- 主题系统管理
- 工作区管理
- 设置管理
- IPC 通信协议
- 核心业务逻辑

**依赖**：
- `@note-studio/shared`

**特点**：
- 不包含 UI 逻辑
- 可在主进程和渲染进程使用

### 3. `@note-studio/ui` - UI 组件库

**职责**：
- React 组件库（基于 shadcn/ui）
- 主题样式
- UI 相关的 Hooks 和 Contexts
- UI 工具函数

**依赖**：
- `@note-studio/core`
- `@note-studio/shared`

**特点**：
- 纯 UI 组件
- 不包含业务逻辑
- 高度可复用

### 4. `@note-studio/editor` - 编辑器核心

**职责**：
- Monaco 编辑器集成
- Markdown 编辑器
- 代码高亮
- 编辑器扩展

**依赖**：
- `@note-studio/core`
- `@note-studio/ui`
- `@note-studio/shared`

**特点**：
- 专注于编辑器功能
- 支持多种文件类型

### 5. `@note-studio/plugin-system` - 插件系统

**职责**：
- 插件 API 定义
- 插件管理
- 插件生命周期
- 命令系统
- 事件系统

**依赖**：
- `@note-studio/core`
- `@note-studio/shared`

**特点**：
- 轻量级插件系统
- 简单易用的 API

### 6. `@note-studio/knowledge-base` - 知识库系统

**职责**：
- 文档解析和索引
- 向量搜索
- RAG 系统
- 知识图谱
- 同步功能

**依赖**：
- `@note-studio/shared`
- `@note-studio/ai`

**特点**：
- 独立的知识库系统
- 支持多种文档格式

### 7. `@note-studio/ai` - AI 服务

**职责**：
- AI 提供商集成（OpenAI、Google Gemini 等）
- 模型管理
- 对话功能
- Prompt 管理

**依赖**：
- `@note-studio/shared`

**特点**：
- 独立的 AI 服务
- 支持多种 AI 提供商

### 8. `apps/desktop` - 桌面应用

**职责**：
- Electron 主进程
- 窗口管理
- 系统集成
- 应用入口

**依赖**：所有 packages

**特点**：
- 应用层，组合所有功能
- 包含主进程和渲染进程

## 依赖规则

1. **单向依赖**：
   - 上层可以依赖下层
   - 下层不能依赖上层

2. **同层依赖**：
   - 同层包之间可以有限依赖
   - 需要明确定义依赖关系

3. **禁止循环依赖**：
   - 严格禁止循环依赖
   - 通过依赖注入解决

## 通信机制

### IPC 通信

主进程和渲染进程通过 IPC 通信：

```
渲染进程 ──→ IPC ──→ 主进程
    ↑                  ↓
    └───── IPC ←───────┘
```

### 事件系统

使用事件总线进行组件间通信：

```
组件A ──→ 事件总线 ──→ 组件B
                   ──→ 组件C
```

## 数据流

```
用户操作
   ↓
UI 组件
   ↓
状态管理 (Zustand)
   ↓
IPC 通信
   ↓
主进程处理
   ↓
数据持久化
```

## 插件系统架构

```
插件 ──→ 插件 API ──→ 插件管理器 ──→ 应用核心
                         ↓
                    生命周期管理
                         ↓
                    命令/事件系统
```

## 主题系统架构

```
主题文件 (JSON) ──→ 主题加载器 ──→ CSS 变量
                                    ↓
                              Monaco 主题
                                    ↓
                              UI 组件样式
```

## 知识库架构

```
文档 ──→ 解析器 ──→ 分块器 ──→ 向量化 ──→ 向量数据库
                                           ↓
                                      语义搜索
                                           ↓
                                       RAG 系统
```

## 构建流程

```
源代码
   ↓
TypeScript 编译 (Turbo)
   ↓
并行构建各个包
   ↓
应用层打包
   ↓
Electron 打包
   ↓
生成安装包
```

## 性能优化

1. **代码分割**：按需加载模块
2. **懒加载**：延迟加载非关键功能
3. **缓存**：利用 Turbo 的增量构建
4. **并行**：并行构建多个包

## 安全性

1. **沙箱隔离**：扩展在沙箱中运行
2. **权限控制**：扩展需要申请权限
3. **代码审查**：内置扩展需要审查
4. **数据加密**：敏感数据加密存储

## 可扩展性

1. **插件化**：核心功能通过插件扩展
2. **模块化**：清晰的包边界
3. **API 稳定**：向后兼容的 API
4. **文档完善**：详细的扩展开发文档
